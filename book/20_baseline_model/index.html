    15　Dense Causal LM 基线：先证明训练系统能学习¶

    基线不是最小的玩具¶

    我们要比较 TTT、Loop 和 MoE，必须先有一个不会把数据、目标或恢复问题隐藏起来的 dense baseline。它不追求结构新颖，而要把输入 token 变成下一个 token 的 logits，并在固定数据上稳定降低 loss。

    基线至少固定：tokenizer 和特殊 token、训练/验证 manifest、sequence length、有效 token 预算、初始化、优化器、学习率计划、随机种子、精度、硬件和 checkpoint 格式。之后的结构实验只改变声明的架构变量。

    从 embedding 到输出头：先读懂普通 block¶

    一个普通 causal LM 可以先看成一条形状稳定的流水线：

    \[ \text{token IDs} \rightarrow\text{embedding} \rightarrow\text{attention} \rightarrow\text{MLP} \rightarrow\text{logits}. \]

    输入 \(X\in\{0,\ldots,V-1\}^{B\times L}\) 经过 embedding 变成 \(B\times L\times d\)。每个 attention head 用 \(d\times d_h\) 的投影矩阵产生 Q、K、V，因果 mask 禁止位置读取未来 token；多头结果拼接后再投影回 \(d\) 维。一个标准残差 block 可以抽象为

    \[ H_1=H+\operatorname{Attention}(\operatorname{Norm}(H)), \qquad H_2=H_1+\operatorname{MLP}(\operatorname{Norm}(H_1)). \]

    SwiGLU 形式的 MLP 可以写成

    \[ \operatorname{MLP}(h) =W_2\bigl(\operatorname{SiLU}(W_g h)\odot W_u h\bigr). \]

    最后的输出投影把 \(B\times L\times d\) 变成 \(B\times L\times V\)。因此，读代码时先检查每个残差分支的输入输出宽度，再检查 logits 的最后一维是否等于 tokenizer 的词表大小。仓库中对应的基础实现分布在 models/ttt_e2e/layers.py、attention.py 和 modeling_ttt_e2e.py；具体层类型、Norm 和位置处理以配置和源码为准。

    这条普通路径是控制变量。加入 MLP′、内循环、路由或深度循环以后，必须说明改变的是哪一段计算、哪一组状态和哪一项成本。TTT 不是“把整个 Transformer 换成另一个网络”，而是在声明的位置增加可更新状态及其梯度协议。

    从 logits 到 loss¶

    logits 先不要理解成概率，它只是模型给每个候选 token 的分数。例如词表只有 cat、sat、dog，某个位置的分数是 \((2,1,0)\)，softmax 才会把它们变成和为 1 的概率：

    \[ p_v=\frac{\exp z_v}{\sum_u\exp z_u}. \]

    如果正确答案是 sat，这个分数对应的概率约为 \(0.245\)，负对数似然约为 \(1.407\)。模型把正确答案的概率提高到 \(0.8\) 时，损失降为 \(-\log(0.8)\approx0.223\)。因此交叉熵不是一个抽象的“训练分数”：它直接惩罚模型没有把概率放到正确 token 上。

    模型产生 \(z_{t,v}\)，其中 \(t\) 是位置、\(v\) 是词表 ID。交叉熵为：

    \[ \ell_t=-\log\frac{\exp z_{t,y_t}} {\sum_{v=0}^{V-1}\exp z_{t,v}}. \]

    直接对大词表计算完整 softmax 可能占用显存，因此仓库的 loss.py 提供按 token 和 vocab block 处理的路径。数学目标不因分块而改变；实现只是把求和拆成可执行的块。

    设 \(W=\sum_t m_t\) 为窗口中的有效监督权重。有效平均 loss 为：

    \[ \mathcal L= \frac{\sum_t m_t\ell_t}{\begin{cases} W,&W>0,\\ 1,&W=0, \end{cases}} \]

    其中 \(m_t\) 是可以取分数值的 loss mask。只有总权重为零时才使用安全分母 1；正的分数权重（即使小于 1）必须保留。全零样本没有监督信号，应该被 preflight 单独报告或拒绝，安全分母不把它变成有效训练样本。

    对 logits 的梯度有一个很有用的形式：

    \[ \frac{\partial\ell_t}{\partial z_{t,v}} =p_{t,v}-\mathbf{1}[v=y_t]. \]

    正确 token 的局部梯度是 \(p_{t,y_t}-1\)，其他 token 的局部梯度是 \(p_{t,v}\)。若把 logits 当作彼此独立的参数直接做 SGD，正确项会上升、其他项会下降。实际网络共享参数，反向传播会汇总不同位置的误差信号，再由 AdamW 更新参数，因此不能保证每个样本的正确 logit 都单调上升。

    这个结果可以直接从损失展开得到：

    \[ \ell_t=-z_{t,y_t}+\log\left(\sum_u\exp z_{t,u}\right), \qquad \frac{\partial\ell_t}{\partial z_{t,v}} =-\mathbf{1}[v=y_t]+\frac{\exp z_{t,v}}{\sum_u\exp z_{t,u}}. \]

    第二项正是 softmax 概率，所以才得到上面的 \(p_{t,v}-\mathbf{1}[v=y_t]\)。

    一次最小的梯度更新¶

    先只在 logits 空间做一个手算，隔离“梯度方向”这个概念。仍使用分数 \(\mathbf z=(2,1,0)\)，正确 token 是第二个位置 sat，所以 \(\mathbf p\approx(0.665,0.245,0.090)\)。由 \(\partial\ell/\partial\mathbf z=\mathbf p-\mathrm{onehot}(y)\)，得到：

    \[ \mathbf g\approx(0.665,-0.755,0.090). \]

    如果暂时把 logits 当成可以直接更新的变量，并取学习率 \(\eta=0.1\)，一次普通 SGD 是

    \[ \mathbf z'=\mathbf z-\eta\mathbf g \approx(1.9335,1.0755,-0.009). \]

    更新后正确 token 的分数从 1 增加到约 1.076，softmax 概率从约 0.245 上升到约 0.271。真实训练不会直接把 logits 当参数；它会把 \(\mathbf g\) 沿计算图传回 \(W\)、hidden、embedding 和 MLP，再由 AdamW 结合动量与权重衰减更新参数。这个小例子只证明局部误差信号的方向， 不代表一次更新就能证明模型能力。

    基线配置到底关闭了什么¶

    num_experts = 0
use_fast_mlp = false
inner.enabled = false
loop_mode = none

    这些开关表达“没有额外动态状态、没有路由、没有深度循环”。注意力仍然可以是 sliding 或 full；如果要研究注意力类型，需把它作为独立变量，不能把所有默认项混成一个 baseline 名称。

    本章使用 configs/book/tiny_dense.json，显式关闭 MLP′，令 suffix 长度为零，并关闭内更新。configs/book/tiny_control.json 保留 MLP′、关闭更新，才是与 configs/tiny.json 的 F 变体配对的 C 对照。Dense 与 C 的参数树不同，不能仅用“更新关了”把它们混为一谈。

    训练一步如何发生¶

    ttt/training.py 先根据配置创建 AdamW 和学习率 schedule。每步：

    1. BatchStream 取窗口与 mask；
    2. sequence_loss 对每个样本计算 forward、内循环和有效 loss；
    3. 外循环对静态参数求梯度；
    4. 梯度裁剪并由 Optax 更新参数和优化器状态；
    5. 记录 loss、梯度范数、inner lr、快权重范数和更新时间；
    6. 按 checkpoint_every 保存状态。

    当 inner.enabled=false 时，sequence_loss 仍沿用同一条路径，只是不更新 fast weights。这个共享路径很重要：C/F 对照改变的是更新行为，而不是另一套模型实现。

    用 loss 判断“可学习”¶

    教学运行只需要观察方向和数值健康：

    • loss 是有限值；
    • 多步运行没有立即变成 NaN；
    • 梯度范数不是持续为零或无界增长；
    • 重复恢复后，下一步与未中断运行接近；
    • held-out loss 的计算使用独立 manifest。

    “loss 下降”本身不是能力证明。随机数据也可能在有限步内被记忆，极小样本更容易过拟合。tiny baseline 的任务是验证接口和优化，不是证明架构可扩展。

    可以记录训练 loss 与 held-out loss 的差值。如果训练下降而 held-out 上升，先检查数据切分、重复和采样，再讨论正则化。数据量太小时，曲线只能作为排错信号。

    参数、激活和实际成本¶

    参数量可由模型树叶元素数量统计，但不等于每步激活内存。TTT 还会保存或重算快权重、梯度和 chunk 状态；MoE 的总参数可能很大，但每个 token 激活的专家较少。

    ttt/profile.py 当前提供参数量、fast MLP 参数量、prefill/decode 时间、状态字节、设备峰值内存和 XLA cost analysis。cost analysis 是估计，不是硬件实测；稳态吞吐还需要真实设备运行并排除首步编译时间。

    基线通过后的比较纪律¶

    对于任一新模型，实验表至少包含：

    维度 必须固定或报告
    数据 manifest、有效 token、来源与污染状态
    模型 总参数、激活参数、层结构、词表
    算法 optimizer、学习率、内循环、seed
    系统 GPU、设备数、精度、编译与通信
    结果 train/held-out loss、吞吐、显存、恢复

    如果 TTT 只在更长训练或更多 token 下胜出，应报告预算差异；如果 Loop 每步更慢但质量更好，应同时报告质量-计算曲线。这样 baseline 才是研究参照，而不是一个被快速越过的占位页。

    下一部分进入模型内部：先逐层追踪一个 token，再解释 TTT 的快权重究竟在何时改变。

    本章最小运行、预期证据与失败诊断¶

    先用样例 token 和 tiny 配置启动一个短运行：

    bash scripts/prepare_sample.sh outputs/sample-tokens.npy
JAX_PLATFORMS=cpu bash scripts/run_train.sh \
  --config configs/book/tiny_dense.json \
  --data outputs/sample-tokens.npy \
  --output outputs/baseline-tiny-001

    成功目录至少应包含 experiment.json、environment.json、metrics.jsonl、status.json 和 checkpoint；loss 应为有限数。这里的四步命令没有执行恢复对照，也没有计算独立验证集损失。恢复检查按可复现运行的同配置协议另做；held-out loss 需要独立数据和评估过程，不能从训练日志推断。

    本章小结与下一问¶

    这次最小运行把 logits、masked loss、梯度和 checkpoint 接到一个明确的普通模型配置上。完整研究基线还需要独立验证集评估与恢复对照；四步样例只建立功能检查的起点。统一的指标、污染和统计协议见评估与统计协议。下一部分沿着同一 token 进入前向路径，明确快权重在哪一刻改变。
