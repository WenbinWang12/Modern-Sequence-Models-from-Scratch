    15. Dense causal-language-model baseline¶

    From logits to loss¶

    Logits are scores, not probabilities. If a vocabulary contains cat, sat, and dog, scores \((2,1,0)\) become probabilities only after softmax:

    \[ p_v=\frac{\exp z_v}{\sum_u\exp z_u}. \]

    If the correct token is sat, this example gives probability about \(0.245\) and negative log-likelihood about \(1.407\). Raising the correct probability to \(0.8\) lowers the contribution to \(-\log(0.8)\approx0.223\). Cross-entropy therefore measures how much probability the model placed on the observed next token.

    The dense baseline is the control for TTT, Loop, and MoE. It fixes tokenizer, manifests, sequence length, effective token budget, initialization, optimizer, schedule, seed, precision, hardware, and checkpoint format before adding dynamic state or routing.

    From embedding to the output head: read an ordinary block first¶

    A dense causal LM can first be viewed as a shape-preserving pipeline:

    \[ \text{token IDs} \rightarrow\text{embedding} \rightarrow\text{attention} \rightarrow\text{MLP} \rightarrow\text{logits}. \]

    Input \(X\in\{0,\ldots,V-1\}^{B\times L}\) becomes \(B\times L\times d\) after embedding. Each attention head uses \(d\times d_h\) projections to produce Q, K, and V. The causal mask prevents a position from reading future tokens; concatenated heads are projected back to width \(d\). An abstract residual block is

    \[ H_1=H+\operatorname{Attention}(\operatorname{Norm}(H)), \qquad H_2=H_1+\operatorname{MLP}(\operatorname{Norm}(H_1)). \]

    An MLP with a SwiGLU-style gate can be written as

    \[ \operatorname{MLP}(h) =W_2\bigl(\operatorname{SiLU}(W_g h)\odot W_u h\bigr). \]

    The output projection maps \(B\times L\times d\) to \(B\times L\times V\). When reading code, check residual input/output widths first, then check that the final logits axis equals the tokenizer vocabulary size. The repository's base implementation is distributed across models/ttt_e2e/layers.py, attention.py, and modeling_ttt_e2e.py; exact layer types, normalization, and positional handling come from the configuration and source.

    This ordinary path is the control. After adding fast MLPs, inner updates, routing, or repeated depth, state which computation, state, and cost changed. TTT does not replace the entire Transformer with an unrelated network; it adds an updateable state and a declared gradient protocol at selected positions.

    For logits \(z\) at position \(t\) and target \(y_t\):

    \[ \ell_t=-\log\frac{\exp z_{t,y_t}} {\sum_v \exp z_{t,v}}. \]

    The repository can compute cross-entropy in token and vocabulary blocks, preserving the same objective while reducing peak memory. Let \(W=\sum_t m_t\) be the total supervision weight in a window. The masked loss divides the weighted loss sum by \(W\); only when \(W=0\) does the implementation use a safe denominator of \(1\). A positive fractional weight below \(1\) is kept as written, and an all-zero mask is reported as having no supervision.

    \[ \mathcal L= \frac{\sum_t m_t\ell_t}{\begin{cases} W,&W>0,\\ 1,&W=0. \end{cases}} \]

    The baseline disables experts, fast MLP, inner updates, and loop mode. It can still choose sliding or full attention, but attention type must be recorded as a separate variable.

    Each training step samples a window, runs sequence_loss, computes outer gradients, applies Optax, records loss and state statistics, and periodically checkpoints. A finite decreasing loss is a health signal, not evidence of broad capability; tiny data can simply be memorized.

    The gradient with respect to one logit has a simple form:

    \[ \frac{\partial\ell_t}{\partial z_{t,v}} =p_{t,v}-\mathbf{1}[v=y_t]. \]

    The correct token has local derivative \(p_{t,y_t}-1\), while other tokens have derivative \(p_{t,v}\). If logits were independent parameters updated directly by SGD, the correct score would rise and the others would fall. A real network shares parameters: backpropagation combines error signals across positions before AdamW updates those parameters. Each example's correct logit is therefore not guaranteed to rise monotonically.

    We can derive it by expanding the loss:

    \[ \ell_t=-z_{t,y_t}+\log\left(\sum_u\exp z_{t,u}\right), \qquad \frac{\partial\ell_t}{\partial z_{t,v}} =-\mathbf{1}[v=y_t]+\frac{\exp z_{t,v}}{\sum_u\exp z_{t,u}}. \]

    The second term is exactly the softmax probability, which gives the form \(p_{t,v}-\mathbf{1}[v=y_t]\).

    One minimal gradient update¶

    Use the same logits example to isolate the direction of the error signal. Let \(\mathbf z=(2,1,0)\), with the second token (sat) as the target. Then \(\mathbf p\approx(0.665,0.245,0.090)\), and \(\partial\ell/\partial\mathbf z=\mathbf p-\mathrm{onehot}(y)\) gives

    \[ \mathbf g\approx(0.665,-0.755,0.090). \]

    If logits were temporarily treated as directly updateable variables, a plain SGD step with \(\eta=0.1\) would be

    \[ \mathbf z'=\mathbf z-\eta\mathbf g \approx(1.9335,1.0755,-0.009). \]

    The correct score rises from 1 to about 1.076, and its softmax probability rises from about 0.245 to about 0.271. Real training does not optimize logits directly: it propagates \(\mathbf g\) through the computation graph into the output projection, hidden state, embedding, attention, and MLP, then AdamW updates the parameters. This calculation demonstrates the local direction of one gradient; it does not establish model capability.

    What the baseline disables¶

    num_experts = 0
use_fast_mlp = false
inner.enabled = false
loop_mode = none

    This chapter uses configs/book/tiny_dense.json, which removes MLP-prime, sets suffix length to zero, and disables inner updates. configs/book/tiny_control.json instead retains MLP-prime while disabling its update, making it the C control paired with F in configs/tiny.json. Dense and C have different parameter trees. Attention may still be full or sliding; its type remains a separate experimental variable.

    One training step and one recovery step¶

    The training path creates the AdamW schedule from the resolved configuration, samples a window and mask, computes sequence_loss, differentiates the outer objective, clips and updates gradients, records state statistics, and writes a checkpoint at the configured interval. With inner.enabled=false, it still uses the same sequence-loss path and only disables the fast-state update; this makes the C/F comparison easier to interpret.

    Recovery is part of the baseline. A resumed run must restore parameters, optimizer statistics, global step, sampler state, data fingerprint, and the next input order. Repeating a checkpoint and comparing the next loss to an uninterrupted run is a stronger check than verifying that a file can be opened.

    What a falling loss does and does not show¶

    For a teaching run, check finite loss, nonzero and bounded gradients, no immediate NaNs, continuity after restore, and held-out loss from an independent manifest. A falling training loss alone is not evidence of capability: a tiny corpus can be memorized. If training loss falls while held-out loss rises, inspect split contamination, duplicate documents, and sampling before changing the architecture.

    Parameters, activation memory, and measured cost¶

    Parameter count is the sum of the numbers of scalar elements in the parameter-tree leaves, not the number of leaves. For example, one \(16\times32\) matrix is one leaf containing 512 parameters. Parameters are also distinct from activation memory. TTT may retain or recompute fast weights, gradients, and chunk state; MoE may have many total parameters while activating only a few experts per token. The fields produced by ttt/profile.py should be read separately: parameter counts, runtime state sizes, timing, and compiler cost estimates answer different questions. Steady throughput requires a real-device run after excluding compilation.

    For each later comparison, report data and tokens, total and active parameters, optimizer and inner-loop settings, hardware and precision, compile and steady cost, memory, communication, training and held-out loss, and restore behavior. The next part follows a token through the TTT forward path.

    Minimal run, evidence, and failure diagnosis¶

    Start with the sample tokens and tiny configuration:

    bash scripts/prepare_sample.sh outputs/sample-tokens.npy
JAX_PLATFORMS=cpu bash scripts/run_train.sh \
  --config configs/book/tiny_dense.json \
  --data outputs/sample-tokens.npy \
  --output outputs/baseline-tiny-001

    The expected directory contains experiment.json, environment.json, metrics.jsonl, status.json, and a checkpoint, with finite loss. This four-step command does not perform a restoration comparison or compute held-out loss. Apply the same-configuration protocol in Reproducible runs separately; held-out loss requires independent data and an evaluation procedure and cannot be inferred from the training log.

    Summary and next question¶

    This minimal run connects logits, masked loss, gradients, and checkpoints to an explicit ordinary-model configuration. A complete research baseline still requires independent evaluation and a restoration comparison; four sample steps establish a functional starting point. The shared metric, contamination, and statistical protocol is in Evaluation and statistical protocol. The next part follows the same token through the forward path and identifies when fast weights change.
