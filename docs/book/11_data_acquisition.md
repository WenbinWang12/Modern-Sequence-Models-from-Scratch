# 11. 数据获取、许可与溯源

## 数据进入仓库之前

数据获取不是下载一个文件然后交给 tokenizer。它首先是一个来源管理问题：我们要知道数据来自哪里、由谁发布、在什么版本下获得、是否允许研究和再分发，以及未来能否取得同一份内容。

如果这些信息缺失，训练结果即使数值很好，也很难成为一个可以公开复现的基模。数据许可、隐私和第三方内容不能由训练脚本自动推断，必须在进入处理流水线前单独审查。

## 来源记录

每个来源保存一份 source.json 或等价记录：

~~~json
{
  "source": "dataset-a",
  "url": "https://example.org/data",
  "version": "2026-01",
  "license": "CC-BY-4.0",
  "downloaded_at": "2026-11-07T00:00:00Z",
  "raw_sha256": "...",
  "notes": "允许研究使用，发布前再次核对条款"
}
~~~

version 应描述发布方版本或下载快照，不能只写“最新版”。raw_sha256 用于确认文件没有被替换；如果来源本身是不断变化的网页集合，还要记录抓取日期、过滤规则和 URL 列表摘要。

仓库不提交大体积原始语料，而是提交 schema、处理配置、来源记录和统计报告。原始文件放在有访问控制的对象存储中，manifest 只引用它的摘要和位置。

## 许可与风险边界

至少分别检查：

- 原始数据的许可和地域限制；
- tokenizer 训练数据是否受同一许可约束；
- 文档中嵌入的第三方代码、图片或个人信息；
- 评测集、测试集和已发布模型数据的污染风险；
- 训练后模型和中间数据能否按计划公开。

“公开可下载”不等于“可以任意再分发”。许可判断应记录结论和依据，不能只保留一个 license 字符串。

## 代码入口与产物

数据源的声明文件位于 data 处理配置和 manifest 目录；训练前由 data loader 读取 manifest，而不是扫描目录中的任意文件。每个处理阶段都应写出：

1. 输入文件及摘要；
2. 处理配置和代码 commit；
3. 输出文件及摘要；
4. 文档数、字符数、token 数和过滤原因。

这样，数据版本就和模型 checkpoint 一样具有身份。
