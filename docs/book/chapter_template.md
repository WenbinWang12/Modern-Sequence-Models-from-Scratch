# 书籍写作与审稿约定

本书面向第一次系统学习模型训练的读者。正文要解释问题、建立概念、推导关系，并让读者能通过小实验检查自己的理解。仓库说明、研究计划和审稿记录不能代替教材正文。

## 章节围绕理解过程组织

小节标题由本章的问题决定，不要求所有章节使用相同的十个标题。一次完整的教学过程通常包含：为什么需要这个概念；具体输入或小例子；定义与适用条件；从已知事实走到结论的推导；对应实现；可观察结果及其解释。

这些是整节或整章需要完成的功能，不是要求每个段落都同时具备公式、代码、命令、失败诊断和小结。过渡段只需说明前后关系，定义段可以专注于消除歧义。不要为了填模板，在“下一章”之后又添加重复命令和第二次小结。

先列章节的概念依赖：读到这一节时，读者已经知道什么，这里新增什么。首次使用的向量、条件概率、自然对数、梯度、采样、缓存、并行等术语，应在当处解释，或明确链接到此前已经完整讲解的位置。不要把“读者应该知道”作为省略步骤的理由。

## 例子与推导

重要概念至少有一个足够小的例子，读者能检查每一步。说明数字是手工构造、公式计算还是实测结果。教学 ID 不得冒充真实 tokenizer 输出；预测输出不得冒充运行日志。

数学推导写明对象、维度、索引、单位和适用条件。中间步骤应解释为什么成立，例如由条件概率定义、对数恒等式或求和归一化得到。用反例检查容易混淆的概念：窗口平均与 token 平均、loss mask 与 attention mask、状态大小与总显存、参数共享与计算量相同。

类比用来引入概念，正式定义负责限定类比。不能只用“记忆”“学习”“专家”之类比喻代替算法。实现代码应在概念建立之后出现，并说明公式如何对应到输入、输出和状态。

## 数学记号与代码名称

遵循 [统一记号](notation.md)。数学对象使用 LaTeX，实际路径、命令、API 和字段用代码格式。教学变量与真实 loader 接口需要明确区分。新增符号先在当节定义，再检查全书是否冲突。

同一个词不要混用两个轴：层栈的 prefix/suffix 不等于文本的较早/较晚位置；外循环 step 不等于内循环 chunk；token ID 的零起点不等于数学位置的索引约定。

## 实践证据

命令应具备可获得的输入、所需环境、明确输出路径和检查办法。真实样例优先使用已提交 fixture；需要读者自备的语料明确说明来源和 schema。路径占位符不属于可直接复制的首跑命令。

核对 CLI 参数、配置字段和输出 schema 的实际实现。区分训练器自动生成文件与建议手工保存的报告。尚未接入训练器的配方、接口或研究方向，明确描述为独立示例或待实现能力。

运行成功只能支持其范围内的结论。形状检查不证明因果性，有限 loss 不证明泛化，CPU 不证明 GPU 性能，tiny 不证明规模扩展。可复现结果需要实际运行产物、代码版本、环境、输入摘要和协议；不能用文字保证代替。

遵守用户指定的测试机器。本项目 CPU 执行验证使用指定远端节点；无法连接时记录待运行，不转到本地执行。

## 逐段审稿

每轮审稿固定 Git 快照，给正文、代码、公式、表格和图注分配文件内编号，记录行号和段首。编号用于编辑报告，不出现在读者正文中。

每个段落检查四件事：它回答什么问题；是否依赖未解释概念；内容及适用范围是否正确；是否自然承接前后文。涉及数学、代码、图片或双语时，再增加相应的专项检查，不机械要求所有段落填满同一张表。

处理结论采用保留、改写、补写、移动、合并、删除或待核验，并留下具体理由。自动提取的段落清单仅证明建立了清单，不能标记成人工审读完成。审稿人必须给出实际阅读范围和没有检查的部分。

缺陷分为：
- P0：事实、数学、实现或实验定义错误，会误导读者或使操作不可执行。
- P1：关键背景、推导、例子、实践或双语内容缺失，读者无法完成理解链。
- P2：措辞、组织、图注、排版与可读性问题。

写作者修改后，由另一名审稿者复核。自审可以发现问题，不能替代独立批准。关闭错误项不等于达到出版标准；新增段落也必须进入下一轮审查。

## 图与双语

图必须回答一个文字不容易直接说明的问题，例如两个轴的关系、状态何时变化、边界目标怎样移位。关键图保留可编辑矢量源文件，统一字体、线宽、留白和配色。图注说明如何读图；标签、方向和公式必须与正文一致。

SVG/XML 合法不代表视觉验收通过。需要检查实际网页中的缩放、窄屏、深浅背景、中文字体、公式和文字是否溢出；还要检查导出版本是否清晰。没有看到渲染图，不声称配图质量已通过。

中英文保留同一概念、条件、推导、数字、代码、输入和结论边界。语言可以自然调整；不能用字数比例判定翻译质量，也不能让英文成为中文的摘要。公式和命令改动需要双向核对。
