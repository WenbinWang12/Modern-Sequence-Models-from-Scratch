## AD3-01 / P1：恰好达到重复阈值的文本被保留

位置：`examples/book/cleaning_walkthrough.py::inspect_record`；第 6 章“至少达到阈值”的说明。

最小反例为 `A.\nB.\nC.\nD.\nA.`：五个非空行，四个不同内容，14 个码点，不触发默认最小长度；多出的重复行占比是精确的 1/5。阈值为 0.2 时，包含等号的拒绝规则应命中。原实现先算 `1 - 4 / 5`，二进制浮点减法得到略小于 0.2 的数，随后比较为假。该误差改变样本去向，而非只改变显示精度。[Python 浮点数说明](https://docs.python.org/3.12/tutorial/floatingpoint.html)

修复为整数计数构造 `Fraction(1, 5)`，与 `Fraction(str(parsed_threshold))` 比较。CLI 仍先解析成 Python `float`；这里精确保留的是**解析后参数的十进制表示**，不是任意命令行小数字符串的全部原始位数。报告保留该表示、重复行数与显示用近似比例，规则版本升为 `cleaning-walkthrough-v2`。双语正文只在实现说明处解释边界，避免把浮点细节插入清洗主线。

新增检查覆盖 0.2 的两侧邻近浮点数、恰好 0.2，以及阈值 0 和 1。它读取实际输出文件，核对去向与计数。手算预期依次为拒绝、拒绝、保留；阈值 0 对适用且无重复的五行 prose 仍拒绝，阈值 1 对五个相同行的比例 4/5 不拒绝。这些端点是规则语义检查，不是推荐配置。

## AD3-02 / P1：重复 JSON 字段名被解析器静默选值

位置：`acquisition_walkthrough.py::read_records`、`cleaning_walkthrough.py::run`、`split_walkthrough.py::load_records`。

反例一：`{"text":42,"text":"A sufficiently long text"}`。默认解析器只保留后一个字段，schema 检查看不到前一个错误值。反例二：一个记录具有两个不同的 `split_group` 字段，切分报告仍可能声称组界限已检查，但源记录的组身份从未消歧。嵌套 metadata 也具有相同问题；`text` 与 JSON 转义拼写 `te\u0078t` 会解码成相同键。[Python 对重复字段的默认行为](https://docs.python.org/3.12/library/json.html#repeated-names-within-an-object)

三个通用输入入口现通过 `object_pairs_hook` 拒绝任意层级同一对象内的重复字段名。获取和切分在创建输出前失败；清洗归入 `invalid_json` 并保存原始行与诊断，继续处理其他行。规则不禁止两个不同对象拥有同名字段，也不把这项检查冒充跨文档 ID 唯一性检查。去重脚本只读取其固定教学 fixture，未扩大为通用语料入口。

这是本书的无歧义输入约定。RFC 要求字段名宜唯一，确实允许接收端采取不同处理方式；因此双语正文没有把所有重复字段一概说成 JSON 语法错误。[RFC 8259 §4](https://www.rfc-editor.org/rfc/rfc8259#section-4)

新增检查覆盖顶层 `text`、转义后重名的 `text`、`split_group`、嵌套对象、数组里的嵌套对象。检查同时要求获取与切分不留下输出目录，清洗保留原始输入行。`data_checks.py` 现在有 12 个测试方法，README 已同步；尚未执行这些新检查。

## AD3-03 / P2：NFC 的说明不宜暗示任意语义的无损保证

位置：第 7 章“比较对象”双语开头。

原句“不会把不同含义的单词变成同一个词”容易被新手理解为通用语义保证。NFC 是规范等价规则，不是判断文档含义的算法；某些编码区分会消失。例如 Unicode 的规范分解说明中，U+212B ANGSTROM SIGN 与 U+00C5 LATIN CAPITAL LETTER A WITH RING ABOVE 共享完整分解。这里没有据此断言普通文字语义一定受损，只撤掉过强保证。[Unicode UAX #15：Singleton Exclusions](https://www.unicode.org/reports/tr15/#Singleton_Exclusion)

正文改为区分规范等价、翻译和语义判断，同时重申这是所选比较表示，保留记录仍保存原始正文。无需因此修改既定 NFC 比较策略。

## 已尝试推翻但未成立的结论

- 清洗记录守恒的观测单位明确为非空输入行；13=5+8 与 10 次诊断命中不是同一计数，默认样例手算一致。
- 去重示例的集合、四行签名、候选 AB/AD/BD/BC 和精确相似度一致。两条阈值边 AB/BC 不能推出删除两篇；只与已保留代表比较时保留 A/C/D，文档守恒为 5=3+1+1。
- MinHash 的均匀排列假设、独立行的方差公式及 LSH 的独立分带条件已明确。固定四行没有被当成随机重复实验；207/256 与 184/625 的手算正确。
- 切分的期望与方差针对理想独立组分配，正文没有声称固定 SHA-256 输出提供随机性证明。90/10 两组例子无法恰得 20 篇验证文档，正确显示组比例与文档比例的区别。
- 获取脚本重新读取保存的对象，不能只修改记录数而通过完整记录比较。切分失败对照在内存中制造错误，不写进正常产物。生产去重、近重复污染、任意输入等尚未实现能力均未被扩张成当前验证结论。
