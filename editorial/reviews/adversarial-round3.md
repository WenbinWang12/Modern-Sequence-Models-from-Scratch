# 第三轮：用反例推进修订

起点：`fe3e52e`。本轮把“能否找到推翻现有表述的最小反例”作为审阅方式。审阅、修改、交换复核分别记录；不以文字更长或图源更多作为质量通过证据。

## 发现和处置

| 问题 | 反例或核查依据 | 处置 |
|---|---|---|
| 清洗阈值边界 | 五行四种文本，重复比例为 1/5；`1 - 4/5` 的浮点值可能略小于阈值 0.2，违反“达到阈值即拒绝” | 使用计数的精确分数比较；明确阈值来自参数解析后的十进制表示，增加等于、两侧及端点检查 |
| JSON 重复字段 | 一条记录两次出现 `text` 或 `split_group`，默认读取器只保留最后一个 | 三个接受用户输入的教学入口拒绝任意层级重复键；清洗仍保存拒绝原行，区分本书约定与 JSON 规范措辞 |
| 正监督权重小于 1 | 单个目标权重 0.5 时，`max(sum(mask),1)` 得到半份损失而非加权均值 | 仅对零分母使用安全值 1，统一序列、内循环和外循环归一化；同步全书记号和教学推导 |
| 多设备稀疏监督 | 即使原 mask 二值，跨设备平均后的分母也可能小于 1 | 保留正分母的实际值；增加逻辑 CPU 设备下与单设备全局均值/更新的对照检查 |
| 来源摘要错配 | 编码 A 以后源文件变成 Z，结束时哈希会把 Z 的身份附到 A 的 token 上 | 摘要覆盖实际消费字节，并与前后源摘要核对；不一致时不发布成功 manifest |
| 存储入口改变监督 | 单 NPY 的所有目标权重默认 1，分片会屏蔽 BOS 目标，空白文本政策也不同 | 两版明确 A/B 的五个目标对照；不把切换准备入口描述成纯存储变化 |
| 序列长度含义 | 原始窗口需要 `L+1` 个 token，模型有 `L` 个预测位置 | 统一 notation 与 packing 章，给 `rows(starts,5)` 对应四次预测的实例 |
| 图示范围过强 | 清洗文件同时含 `original_text`，并非“只有训练正文”；编码过程会产生 token 序列，但不新增词表项 | 两版图回改为统计视图不覆盖正文、编码不扩充词表 |

数据侧反例与修复见 [数据对抗审阅](adversarial-data-round3.md)，模型及分片见 [token 管线对抗审阅](adversarial-token-pipeline-round3.md)。两名审稿者交换复看对方修复，主代理另外检查损失测试与实际消费字节的实现。

## 视觉修订与出版产物

清洗、去重、BPE 三组图重排为一致的暖白与深墨版式，分别通过正文/统计分支、候选关系图和保持字符跨度的合并轨迹表达机制。用线型、标签和编号补充颜色，删除图中与正文重复的细密表格，放大核心标注。BPE 的 TikZ 与 SVG 同步。

页面加入可键盘聚焦、可水平滚动的图区，以及 SVG、高清 PNG、矢量 PDF 和可用 TikZ 的下载入口。图源与布局取舍见 [设计记录](figure-design-round3.md)。

PNG/PDF 在文档发布流程中生成，属于出版资产，不执行模型、数据或 pytest 检查。导出清单记录图源摘要、产物摘要、库版本和字体；PDF 来自 SVG 转换，不能作为 TikZ 已编译的证据。实际图形导出后的视觉发现与回改另记在 [视觉复核](figure-visual-round3.md)。

## 明确保留的边界

- 新的模型、数据、分布式回归仅编写与静态审读。按用户要求，远端暂不可用时先不执行，没有改在开发电脑运行。
- 正权重归一化修复不等于整条训练栈已经验收；零 NLL 也不表示优化器参数一定不动。
- 来源摘要约束绑定所消费的字节，不证明输入文件从未改变，也不是多写入进程的锁。
- 普通 NPY 与分片入口的现有监督政策保留；若未来统一，必须作为数据版本变化处理。
- 图的实际渲染与代码执行是不同证据；最终网页的交互与窄屏还需实际浏览器检查。
- 整本书仍在修订中。本轮具体问题的解决不等于全部章节达到出版标准。
