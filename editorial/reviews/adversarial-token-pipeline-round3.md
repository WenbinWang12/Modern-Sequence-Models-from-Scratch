## P1：允许分数 mask，却把所有小于 1 的正分母截成 1

**反例。** 两位置损失为 2、4，权重为 1/4、1/2。加权和为 2.5，总权重 0.75，平均应为 10/3；旧代码除以 `maximum(0.75, 1)` 得 2.5。更小的例子只有一个权重 0.5、损失为 l 的目标：单样本先产生 0.5l，外循环又乘 0.5 并除以 1，成为 0.25l，而正确加权平均为 l。整体缩放同一组权重，错误实现会改变损失及梯度。

**依据。** `TokenDataset` 明确接受 `[0,1]` 有限权重，交叉熵函数也按数值乘权；因此直接禁用分数掩码会改变既有 API 语义。应修正平均，而不是隐藏反例。

**修订。** `ttt/inner_loop.py` 的块损失与序列损失，`ttt/training.py` 的外循环目标和 NLL，均保留真实正权重和，仅在零权重时使用安全分母 1。16 两版用单位置负对数概率、分数手算、跨样本加权依次推导；05 和 notation 的分母同步。明确零 NLL 只涉及语言建模项，不证明辅助项或带动量/权重衰减的更新为零。

**新增回归（未运行）。** `tests/test_weighted_loss.py` 比较真实小模型的损失和参数梯度与独立 logits 参考；检查统一缩放权重后真实内循环更新、后续 logits 不变；检查外循环损失、梯度范数和无动量 SGD 参数更新；全零 mask 检查 NLL 和无辅助项的 SGD 特例。

### 同一缺陷会影响二值掩码的多设备训练

两设备只有一台有一个有效目标，局部目标数是 1、0。`pmean` 后分母为 0.5。旧代码将其截成 1，再平均两台设备的目标，得到正确损失和梯度的一半。修订保留分母 0.5，最后一次 `pmean` 恢复全局正确比率。这里无需任何分数 mask 就会出现错误。

`tests/test_weighted_loss.py` 新增独立子进程中的两逻辑 CPU 设备 `pmap` 回归，比较全 batch 单设备与分布式的真实 NLL、目标及每个参数副本；测试文件没有被执行。JAX 对 `pmean` 的跨轴平均语义见 [官方文档](https://docs.jax.dev/en/latest/_autosummary/jax.lax.pmean.html)。当前统计中的内循环范数等仍是样本/设备平均；没有把这些指标宣称为全局 token 计数。

## P1：来源摘要可能对应处理后的新文件，而非实际 token 来源

**反例。** 输入一行 A；tokenizer 编码 A 时把源文件改成 Z；旧实现成功写出 A 的 token，却在结束时计算 Z 文件的摘要。分片 hash 正确、清单字段齐全，但来源身份错误。

**修订。** `prepare_sharded_data` 计算读前摘要、实际消费的原字节流摘要、发布前摘要；三者不一致时拒绝发布 manifest。以二进制行读取，避免 CRLF 和空行在摘要中消失；manifest 保存消费摘要。失败可能留下没有成功清单引用的分片，文稿没有声称自动回滚所有文件。

**边界。** 三次摘要比较不是期间不可变的数学证明，不阻止改动后恢复、检查后的修改或多个写入任务竞争。17 两版明确不可变输入、单写入者输出目录和可信参考摘要的前提。

**新增回归（未运行）。** `tests/test_dataset.py` 的编码中 A→Z 突变要求抛出异常且无 manifest；CRLF 加空行样本要求输入摘要覆盖完整字节，并读出预期 `[1,68,2,1,69,2]`。交叉二审指出，单个 A→Z 反例只锁定前后摘要，不能防止未来误删消费摘要；因此追加 A→Z→A 对照：预摘要读取 A 后替换成 Z，实际编码 Z 时恢复 A，前后摘要相同但消费摘要不同，仍必须失败且不发布 manifest。

## P2：单 NPY 与分片入口不是仅存储布局不同

**反例。** byte tokenizer 编码 A、B，两个入口均可得到 `[1,68,2,1,69,2]`。整个流五个目标的 mask，单 NPY 是 `[1,1,1,1,1]`，分片是 `[1,1,0,1,1]`，差别是前文 EOS 预测后文 BOS。另输入空字符串、A，单 NPY 保留 `[1,2,1,68,2]`，分片跳过空字符串，只保留 A 的三个 token。

**修订。** 16 两版明确入口差异、连续上下文与边界监督的区分；17 的“改变分片大小不应改变逻辑流”增加 token 和 mask 完全一致的前提。没有静默修改历史数据政策。`tests/test_dataset.py` 新增上述实际入口回归，待远端运行。

## P2：三个不同长度被同一 L / length 混用

原 15 将任意文档编码长度写成 L；16 的英文把 `rows(..., length)` 与 `BatchStream.sequence_length` 混称；17 的手算读 5 个原始 token 后又说长度 5 需要多取一个 token，未区分两个定义。

**修订。** 15 文档 token 数为 `n_u`；全书 L 为模型输入位置数；BatchStream 为 L 个预测位置读 L+1 个原始 token；`TokenDataset.rows(starts, 5)` 返回 5 个 token、4 个目标权重。中英记号表和 16/17 的例子同步。

## P2：摘要与词表大小被写成过强的身份证明

**反例。** 两个大小 259 的词表互换 ID 68 与另一 ID 的含义。token 范围和清单词表大小完全通过，不能识别映射变化。若攻击者或错误流程连同清单一起重写摘要，仅比较新清单也不能确认旧版本。

**修订。** 17 两版明确 tokenizer 文件摘要、版本、特殊 token ID 与 `vocab_size` 是不同检查；摘要需要可信参考、依赖碰撞安全前提，并不证明许可、质量或后续不可变。中文补齐英文已存在的累计端点一般式和文档反向索引缺失，逐步手算 `p=6` → 第二片局部 `2` → token 22。

## BPE 数学与图源复核

四词 `cat/cats/cap/caps` 频数 5/2/3/1，首轮 `(c,a)` 计数 11；五个选中时计数 11/7/5/4/3 与 rank 0–4 一致。未见词 `catt` 应只用 rank 0、1，得到 `cat,t,</w>` 和教学 ID `[7,5,0]`；第二个 t 阻断 rank 2，词尾标记不是 EOS。这些结论与脚本、正文、图源一致。
