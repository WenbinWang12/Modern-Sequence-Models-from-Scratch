## 发现、修补和仍待验证的事项

| 编号 | 严重度 | 位置与证据 | 处理与剩余工作 |
|---|---|---|---|
| C2-01 | P0：输入可导致非标准 JSON 输出 | 原 `cleaning_walkthrough.py` 只有 `parse_constant`，它拦截 `NaN/Infinity` 字面量，但默认浮点解析会把合法 JSON 数字 `1e999` 变成 `inf`。例如合法记录的额外元数据 `"score":1e999` 会随 `dict(record)` 保留，再被默认 `json.dumps` 写成 `Infinity`，违反声明的 JSON 产物格式。 | 已增加 `parse_finite_float`，数值溢出抛出 `ValueError` 后沿拒绝日志路径处理；全部三个 JSON 输出口增加 `allow_nan=False`。两版解释这是本读取器支持范围，不说 `1e999` 本身语法非法。待远端检查正负溢出、嵌套溢出、普通有限小数，以及标准样例计数不变。 |
| C2-02 | P2：数学条件遗漏 | 误删率公式分母为“应保留记录总数”；若标注样本全为应拒绝，原文没有说明 `0/0`。 | 已在中英文公式后补至少一个应保留样本的条件，分母为零时记未定义，不填零误删率。需另一审稿人复看新增句。 |
| C2-03 | 验收未完成，不冒充已经发现的版式错误 | SVG 使用 1120 宽 viewBox，最小标签 13 px；未取得实际页面和窄屏图。 | 必须看真实渲染：四空格是否保留、中英文标签是否溢出、正文宽度缩放后是否可读、背景是否合适。XML 合法或源码排得整齐均不构成视觉通过。 |

有限数缺陷依据 [Python 3.12 JSON 官方文档](https://docs.python.org/3.12/library/json.html) 的 `parse_float`／`parse_constant`／`allow_nan` 语义静态定位，不把文档阅读称为复现运行。`parse_finite_float` 保持普通数值走 Python 原有 float 路径；没有把所有元数据改成 Decimal 或字符串。拒绝的原始输入行仍被保留，便于随后使用支持更大数字范围的工具处理。

新增说明使“结构检查先于文本检查”段较长，但仍按解析限制→结构→正文 Unicode 的因果链组织。后续版式审校可以拆段，不应删除数值范围与 Unicode 的区别。
