## 实际进行了哪些轮次

第一步由四名作者并行写各自负责的内容，补全算例、推导和程序。第二步交换章节：分词作者审获取与切分，去重作者审清洗，清洗作者审分词，主代理审去重。发现的问题回到文件中修复，再对修改处复看，历史意见保留，不改成“从未有问题”。

交叉复审带来的实质修改包括：获取报告改为依据实际落盘文件；切分解析和摘要使用同一次输入快照；清洗拒绝超出有限浮点表示范围的元数据；BPE 和正式 tokenizer 拒绝覆盖旧产物；训练前后核对原始输入与实际训练文本；Unigram 的正号目标明确最大化。验证入口也区分缺少依赖、跳过测试和实际执行。

这些是可定位的审校与修复，不是通过多写一次“审核完成”模拟多轮审稿。逐单元矩阵在链接的独立记录中。

统一入口和切分数值边界又经过[最终独立复看](runner-split-round2-recheck.md)。提交前为 JSONL 与 SVG 固定 LF 换行，避免不同 Git 换行配置无意改变教学输入的字节身份。

## 复现入口与证据状态

`examples/book/README.md` 包含标准库和完整锁定环境两条运行路径。`run_checks.py` 依次执行边界检查与五章实验，输出独立日志和 `validation.json`。正式 tokenizer 检查需要显式启用；源摘要、Python 版本、实际子命令及退出状态写入报告。输出目录均需要新建，BPE 的输出参数是新 JSON 文件。

本轮没有执行新教学脚本、pytest、Ruff 或 TeX 编译。指定远端曾短暂可连接，随后 TCP 连接持续超时；用户明确同意“连不上就先不用了”，因此停止重试，没有改到本地测试。先前准备环境的动作不等于新代码通过验证。

本地仅做文本审读、手算、文件差异检查和编辑。网页构建属于发布流程，状态以对应 GitHub Actions 记录为准；即使构建成功，也只说明生成页面成功，不能代替算法运行或数学/图形视觉验收。
