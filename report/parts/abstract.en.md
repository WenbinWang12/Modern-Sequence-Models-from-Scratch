We implement end-to-end test-time training (TTT-E2E) from scratch: while reading a context, the model runs gradient descent on one set of MLPs in its last few blocks using the text it has just read, and training differentiates through those updates so that the model learns to be updated this way. On two H200 GPUs we trained four models of about 138M parameters at 4,096 context, with identical data, batch order, optimiser and token budget: full attention, sliding-window attention (window 512), a control with TTT's architecture and parameter count but no updates, and TTT-E2E. The corpus is half FineWeb-Edu and half PG-19, {{ n(r.training.swa.tokens_seen) }} GPT-2 BPE tokens in total.

The report measures three factors separately: the extra parameters, the test-time updates, and the meta-learning during training. The no-update control answers the first, switching updates off in the same checkpoint answers the second, and running test-time gradient updates on a model that was never meta-trained (dynamic evaluation) answers the third. On cost, {% if r.training_cost.ttt %}TTT-E2E's training throughput is {{ f2(r.training_cost.ttt.tokens_per_second / r.training_cost.swa.tokens_per_second) }}× that of sliding-window attention, while {% endif %}its per-token inference cost and session state are independent of context length.

We measure the method's limits as well: a verbatim-recall probe and a RULER-style single-needle retrieval task ask how much detail survives compression into weights. Ten public zero-shot benchmarks use a protocol checked metric by metric against lm-evaluation-harness (the GPT-2 cross-check is in Section 4.7), alongside public models trained on one to three orders of magnitude more data. Data audits cover the sampling mixture, duplication between training and evaluation sets, and verbatim occurrences of benchmark items in the training corpus. Every number on this page is produced by a script from raw evaluation output, and that output ships with the repository.
