This report keeps the question inside a matched experiment that can be checked component by component. The four models share the vocabulary, corpus mixture, batch order, optimiser and token budget. The declared differences are the visible context and test-time updates. Tables 1–4 therefore address final loss, position within the context, behaviour beyond the training length and verbatim recall separately. This design separates access to more history from parameter count, and it separates TTT updates from the same architecture with updates disabled.

The TTT-E2E result should be read with both controls. The sliding-window model retains only a fixed recent window, so information from earlier text must be carried indirectly by its state. TTT-E2E updates fast weights with an inner loop after it has read new text. The no-update control keeps the fast-weight parameters but removes that update. A stable difference between these two arms measures the contribution of learning how to update and of applying the learned update at inference. The fast-weight drift in Section 4.6 and the needle probe in Table 5 describe how this state changes with context.

The mechanism has a direct systems cost. Training differentiates through the inner loop, while inference stores fast weights, caches and update boundaries. Table 13 reports training throughput and memory, and Table 14 reports session state and token-by-token decoding speed. These measurements put quality changes beside their resource requirements. Quota interruptions and automatic recovery events remain in the run records, while checkpoints, configurations and data digests preserve the experiment's provenance.

The public benchmarks probe transfer beyond the training distribution. The models are pre-trained base models, and prompt format, answer parsing and context limits affect generation tasks. Tables 6, 8 and 9 should therefore be read together with the raw JSON artifacts. The contamination audit searches for exact matches of normalised question prefixes. Table 15 records its coverage and blind spots. This audit bounds one source of concern and does not test paraphrase, translation or answer-only overlap.

The scale of the experiment determines how far the conclusions can be extrapolated. The main run uses about 130M parameters, 786,432,000 training tokens and a 4,096-token training context, with evaluation extended to 32K. The seed, scale, ablation and official long-context suites should be expanded as resources allow. RULER, LongBench, Chinese evaluations, toxicity and bias evaluations require their own data licences, prompt templates and safety audits. Future runs should retain the matched controls and raw-result archive while increasing model, data and context scale.
