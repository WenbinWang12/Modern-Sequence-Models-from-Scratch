Three things separate TTT-E2E from sliding-window attention: the extra MLP′ in the suffix (parameters), the gradient updates at inference (test-time compute), and the fact that training simulated those updates (meta-learning). Four models plus two dedicated evaluations pull them apart.

{% if r.fig_context_4k.paired.ck_minus_swa %}**The extra parameters alone.** The no-update control has TTT-E2E's architecture and parameter count and runs no inner loop in training or inference. It is {{ f3(-r.fig_context_4k.paired.ck_minus_swa.all.mean) }} nats below sliding-window attention ({{ ci(r.fig_context_4k.paired.ck_minus_swa.all.ci95) }}). The extra {{ M(r.training_cost.ttt.fast_parameters, 1) }} parameters do help, but they account for only part of the total {{ f3(-r.fig_context_4k.paired.ttt_minus_swa.all.mean) }} nat gap.

**The test-time updates alone.** TTT-E2E is {{ f3(-r.fig_context_4k.paired.ttt_minus_ck.all.mean) }} nats below the no-update control ({{ ci(r.fig_context_4k.paired.ttt_minus_ck.all.ci95) }}). The two have identical architecture and parameter count; they differ only in whether the fast weights are updated at inference and whether training simulated that. This is the largest of the three terms.{% endif %}

{% if r.dynamic.ck %}**Are updates enough without meta-learning?** This is the decisive question: if plain test-time gradient descent on any ordinary model gave the same gain, the second-order training pass would be wasted effort. We ran the same inner loop directly on the no-update control, sweeping the test-time learning rate. It barely moves: the best setting reaches {{ f4(min(r.dynamic.ck.lr0p01.validation, r.dynamic.ck.lr0p03.validation, r.dynamic.ck.lr0p1.validation, r.dynamic.ck.lr0p3.validation, r.dynamic.ck.lr1.validation)) }} against {{ f4(r.dynamic.ck.off.validation) }} without updates. The same machinery applied to the meta-trained TTT-E2E takes it from {{ f4(r.dynamic.ttt.off.validation) }} to {{ f4(r.dynamic.ttt.lr1.validation) }}.

What helps, in other words, is **not the act of updating but having been trained to be updated** — which is exactly what the second-order training pass buys.{% endif %}

{% if r.fig_context_4k.paired.ttt_noadapt_minus_ck %}One observation points the other way and is worth recording. Evaluating the trained TTT-E2E with **updates switched off** puts it {{ f3(r.fig_context_4k.paired.ttt_noadapt_minus_ck.all.mean) }} nats *above* the no-update control ({{ ci(r.fig_context_4k.paired.ttt_noadapt_minus_ck.all.ci95) }}). Slow weights trained with updates come to **depend** on them: part of the modelling work has been delegated to the inner loop, and removing it leaves a hole. TTT-E2E is therefore not a feature that can be switched off to save compute; it is a design that has to be adopted as a whole.{% endif %}
