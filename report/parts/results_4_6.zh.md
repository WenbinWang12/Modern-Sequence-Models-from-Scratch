前面几节说明 TTT-E2E 更会利用上下文，但没有说明它**以什么方式**利用。把历史压进固定大小的权重，必然丢掉一些东西；这一节用两个探针去找出丢掉的是什么。

{% if r.recall.ttt %}**逐字回忆。** 把窗口内一段 64 个 token 的原文原样复制到更靠后的位置，看模型在重复段上的损失比未改动文本降低多少。注意力可以直接回看原文，所以全注意力在距离 320 处降低 {{ f2(r.recall.full["320"].gain) }} nat，并随距离缓慢衰减到 {{ f2(r.recall.full["3712"].gain) }} nat。

滑窗注意力的表现是一道断崖：距离 320（仍在 512 窗口内）时降低 {{ f2(r.recall.swa["320"].gain) }} nat，一旦超出窗口就归零甚至变为负值（距离 640 时 {{ f2(r.recall.swa["640"].gain) }}）。窗口之外，它对自己读过的原文没有任何记忆。

TTT-E2E 填上了这道断崖，但填的方式与注意力不同：距离 640 处降低 {{ f2(r.recall.ttt["640"].gain) }} nat，而且此后**几乎不随距离衰减**（3,712 处仍有 {{ f2(r.recall.ttt["3712"].gain) }} nat）。这正是"压进权重"应有的特征——信息不是按距离远近排列的，而是被累积进一组权重里。代价同样明显：它的绝对量只有全注意力的一半左右，压缩确实有损。{% endif %}

{% if r.niah.ttt %}**单针检索。** 按 RULER 的 `niah` 任务构造：在干草堆文本里藏一句"某个键对应的特殊数字是 ⟨7 位数⟩"，然后提问。这些模型都是 1.3 亿参数的基座模型，没有指令微调，直接按精确匹配评分全部为零——这样的全零结果说明不了任何问题。因此我们改为度量"针在场 vs 针被换成无关键值对"时答案对数似然的差：它衡量模型是否真的用到了那根针，即使它说不出完整答案。

在 32K 上下文下，TTT-E2E 的这一指标是 {{ f2(r.niah.ttt.results.books_32768.needle_gain_per_token) }} nat/token，滑窗注意力是 {{ f2(r.niah.swa.results.books_32768.needle_gain_per_token) }}，无更新对照是 {{ f2(r.niah.ck.results.books_32768.needle_gain_per_token) }}。滑窗和无更新对照的数值随上下文变长而持续下滑（针被推到窗口之外），TTT-E2E 则从 4K 到 32K 基本持平。{% endif %}

两个探针指向同一个结论：TTT-E2E 保留的是**随上下文长度稳定、但精度受限**的记忆，而注意力保留的是**精确、但受窗口或成本限制**的记忆。它们不是同一种东西，这也是原论文在针尖检索类任务上落后于全注意力的原因。
