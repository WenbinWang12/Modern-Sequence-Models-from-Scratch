Ablations use smaller models (8 blocks, width 512, 2,048 tokens of context), changing one factor at a time (Table 9, Figure 6).

{% if r.ablations.abl_ttt_ilr0p3 %}**Inner learning rate \(\eta\).** Values of 0.1, 0.3 and 1 give similar results ({{ f3(r.ablations.abl_ttt_ilr0p1.nll) }}, {{ f3(r.ablations.abl_ttt_ilr0p3.nll) }}, {{ f3(r.ablations.abl_ttt.nll) }}), while \(\eta=3\) is clearly worse ({{ f3(r.ablations.abl_ttt_ilr3.nll) }}), falling behind the sliding-window baseline at the same size. This matches Section 4.1: the inner gradient norm sits near the clipping threshold, so most updates are clipped to a fixed step size and \(\eta\) matters little over a wide range — until the step is large enough to destabilise training.{% endif %}

{% if r.ablations.abl_ttt_chunk64 %}**Update chunk \(C\).** 64, 128 and 256 are nearly indistinguishable ({{ f3(r.ablations.abl_ttt_chunk64.nll) }}, {{ f3(r.ablations.abl_ttt.nll) }}, {{ f3(r.ablations.abl_ttt_chunk256.nll) }}). Smaller chunks mean more frequent updates and higher training cost without buying lower loss at this scale, so the main experiment uses the larger \(C=256\).{% endif %}

{% if r.ablations.abl_ttt_suffix4 %}**Number of blocks with fast weights.** One, two and four blocks give {{ f3(r.ablations.abl_ttt_suffix1.nll) }}, {{ f3(r.ablations.abl_ttt.nll) }} and {{ f3(r.ablations.abl_ttt_suffix4.nll) }}: more blocks help slightly, with diminishing returns and a backward pass through each one per chunk.{% endif %}

{% if r.ablations.abl_ttt_window128 %}**Attention window \(k\).** TTT-E2E barely moves across 128, 256 and 512 ({{ f3(r.ablations.abl_ttt_window128.nll) }}, {{ f3(r.ablations.abl_ttt.nll) }}, {{ f3(r.ablations.abl_ttt_window512.nll) }}), while the sliding-window baseline is markedly more sensitive ({{ f3(r.ablations.abl_swa_window128.nll) }} → {{ f3(r.ablations.abl_swa_window512.nll) }}). The fast weights take over work that the attention window would otherwise have to do, which is where the long-context cost advantage comes from.{% endif %}

{% if r.ablations.abl_ttt_matched %}**Parameters matched exactly.** Narrowing every MLP so the total parameter count equals the baseline without MLP′ gives {{ f3(r.ablations.abl_ttt_matched.nll) }}, still well ahead of the sliding window's {{ f3(r.ablations.abl_swa.nll) }}. The gain does not rest on the extra parameter budget.{% endif %}

{% if r.ablations.abl_ttt_fo %}**First-order approximation.** Treating the inner gradient as a constant leaves the forward pass unchanged and makes training cheaper. It scores {{ f3(r.ablations.abl_ttt_fo.nll) }}, matching or slightly beating full second-order training at {{ f3(r.ablations.abl_ttt.nll) }}. At this scale the second-order term through the inner loop is **not required** — a useful negative result, though whether it survives at larger scale is beyond what this report can answer.{% endif %}

{% if r.ablations.abl_swa_iso %}**Matched training time.** Every comparison above fixes the token count, but TTT-E2E is slower per step (Table 12). Using the measured step time, we gave the sliding-window baseline the same wall-clock budget: {{ n(r.ablations.abl_swa_iso.steps) }} steps and {{ M(r.ablations.abl_swa_iso.tokens_seen, 0) }} tokens, about 3.7× the data. It reaches {{ f3(r.ablations.abl_swa_iso.nll) }}, **far better** than TTT-E2E's {{ f3(r.ablations.abl_ttt.nll) }}.

This is the most important negative result in the report. At a fixed token budget TTT-E2E is clearly better; but if the binding constraint is **time or compute** rather than data, spending that time on more data is the better deal at this scale. Section 6 takes this up.{% endif %}
