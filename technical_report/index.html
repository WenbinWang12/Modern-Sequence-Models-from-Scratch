    TTT-E2E 技术报告：从零训练、匹配对照与长上下文评测¶

    版本 1.0　·　2026 年 11 月 18 日

    摘要¶

    我们从零实现了端到端测试时训练（TTT-E2E）：模型一边读上下文，一边用读过的内容对自己最后几层中的一组 MLP 做梯度下降，训练阶段则通过内循环求导，让模型学会“被这样更新”。在两张 H200 上，我们用完全相同的数据、batch 顺序、优化器和 token 预算训练了四个约 1.3 亿参数、上下文 4,096 的模型：全注意力、滑窗注意力（窗口 512）、与 TTT 结构和参数量相同但不做更新的对照，以及 TTT-E2E。训练语料是 FineWeb-Edu 与 PG-19 各半、共 786,432,000 个 GPT-2 BPE token。

    在 PG-19 test 上，TTT-E2E 的每 token 损失比滑窗注意力低 0.072 nat（95% 置信区间 [−0.076, −0.068]），比全注意力低 0.051 nat。差距随可用上下文的长度变化，详见第 4.3 节；把评测窗口延长到训练长度 8 倍（32,768 个 token）的结果见第 4.5 节。 报告把“额外参数”、“测试时更新”和“训练时的元学习”三个因素分开度量：无更新对照回答第一项，同一检查点关闭更新回答第二项，对未经元训练的对照直接做测试时梯度更新（动态评估）回答第三项。成本方面，TTT-E2E 的训练吞吐是滑窗注意力的 0.36 倍，而推理时的会话状态大小和每 token 成本与上下文长度无关。

    我们同样度量方法的边界：逐字回忆探针和按 RULER 构造的单针检索，衡量被压进权重的历史在细节上保留了多少；十项公开零样本 benchmark 使用与 lm-evaluation-harness 逐项核对一致的协议（GPT-2 上的核对结果见第 4.7 节），并与一组训练量大一到三个数量级的公开模型放在同一张表里。数据审计覆盖采样配比、训练与评测集之间的重复，以及 benchmark 题目在训练语料中的逐字出现。本页的每个数字都由脚本从原始评测输出生成，原始输出随仓库发布。

    1 引言¶

    长上下文语言模型在成本上有一个基本矛盾。全注意力让每个 token 都能直接读到此前的全部内容，但每生成一个 token 的计算量和需要保存的状态都随已读长度线性增长。把注意力限制在最近的一个窗口里，这两项都变成常数，代价是窗口之外的内容基本丢失。循环网络一类的方法把历史压进固定大小的状态，问题变成压缩什么、怎样压缩。

    TTT-E2E1 的回答是把历史压进模型自己的一部分权重，并且用梯度下降来压缩。模型一边读，一边在刚读过的文本上做下一个 token 的预测训练，只更新最后几层里的一组 MLP；训练阶段再用元学习让模型为“被这样更新”做好准备。原论文在 30 亿参数、1,640 亿训练 token 的规模上报告：在 128K 上下文内，TTT-E2E 的损失随上下文长度的变化方式与全注意力相同，而推理延迟不随上下文增长。

    本报告从零实现了这一方法，并在两张 GPU 可以完整复现的规模上检验它。我们用同一份数据、同样的 batch 顺序、同样的优化器和同样的训练 token 数训练四个约 1.3 亿参数的模型，回答五个问题：

    1. TTT-E2E 相对滑窗注意力能挽回多少因为看不到远处上下文而损失的预测质量，离全注意力还有多远？（第 4.2、4.3 节）
    2. 收益里有多少来自测试时更新本身，有多少只是因为多了参数？不做元学习、直接对普通模型做测试时梯度更新够不够？（第 4.4 节）
    3. 上下文超过训练长度之后会发生什么？（第 4.5 节）
    4. 把历史压进权重会丢掉什么？（第 4.6 节）
    5. 训练和推理各要付出多少成本？（第 4.10 节）

    此外，第 4.7 节用同一套零样本协议把这些模型和一组公开的同规模模型放在一起，给出绝对水平的参照；第 4.8、4.9 节是消融、随机种子和模型规模实验；第 5 节是数据审计。

    与已有工作的关系。 在测试序列上继续做梯度更新的做法至少可以追溯到动态评估67；快权重8提供了“随序列变化的权重”这一视角；通过内循环求导来学习初始化是 MAML4 的做法，一阶近似见 Reptile5。把测试时训练用于分布外泛化见 Sun 等3，把它做成序列模型的层见 TTT 层2和 Titans9。同样追求常数推理成本的还有状态空间模型和线性循环模型，例如 Mamba10 和 Gated DeltaNet11；限制注意力范围或跨段复用状态的 Transformer 见 Transformer-XL12、Longformer13、Compressive Transformer14 和 Block-Recurrent Transformer15。本报告只实现并评测 TTT-E2E 及其对照，没有重新实现上述其他方法。

    本报告的贡献。

    • 一个完整的 JAX 实现：带二阶导的训练、带状态的流式推理、检查点与恢复，以及一套对正确性做出保证的测试（因果性、外循环梯度、流式一致性）。
    • 一组严格匹配的对照实验，以及能把“参数量”“测试时更新”“元学习”三个因素分开的对照。
    • 超出训练长度 8 倍的评测、逐字回忆探针、公开 benchmark 和与公开模型的同协议比较。
    • 全部数字可追溯：本页的每个数字都由脚本从原始评测输出生成，原始输出和生成脚本都在仓库里。

    2 方法¶

    2.1 记号¶

    记 token 序列为 \(x_1,\ldots,x_{L+1}\)，模型在位置 \(t\) 读入 \(x_{1:t}\) 并预测 \(x_{t+1}\)，\(L\) 是一个训练窗口里的预测位置数。模型有 \(n_\ell\) 个残差块，隐藏宽度为 \(d\)，MLP 中间宽度为 \(d_{\mathrm{ff}}\)，词表大小为 \(V\)。滑窗注意力的每一层只能看到最近 \(w\) 个位置。

    参数分成两部分。慢参数 \(\theta\) 在训练结束后固定，所有序列共用；快权重 \(\phi\) 属于当前这一条序列，随着序列被读入而改变。序列按长度 \(C\) 切成更新块（chunk），第 \(c\) 块包含位置 \(\mathcal T_c=\{(c-1)C+1,\ldots,cC\}\)。\(\phi_{c-1}\) 表示预测第 \(c\) 块时使用的快权重，\(\phi_0\) 是它的初值。

    2.2 模型结构¶

    主干是一个 pre-norm 的 decoder-only Transformer。每个块依次做两件事：

    \[ u=h+\operatorname{Attn}\bigl(\operatorname{RMSNorm}(h)\bigr),\qquad h'=u+\operatorname{MLP}\bigl(\operatorname{RMSNorm}(u)\bigr). \]

    注意力使用旋转位置编码（RoPE，基数 \(5\times10^5\)）和 QK 归一化：query 和 key 在每个头内先做 RMSNorm 再做点积，分数除以 \(\sqrt{d_h}\)。MLP 是 SwiGLU，\(\operatorname{MLP}(v)=W_{\mathrm{down}}\bigl(\operatorname{SiLU}(W_{\mathrm{gate}}v)\odot W_{\mathrm{up}}v\bigr)\)，不带偏置。输入嵌入和输出投影共用同一个矩阵。

    TTT-E2E 只改动最后 \(n_s\) 个块（下文称后段，其余 \(n_\ell-n_s\) 个块称前段）。后段的每个块在注意力和原有 MLP 之间多一个结构相同的 MLP′，它的三个矩阵就是快权重：

    \[ u=h+\operatorname{Attn}(\operatorname{RMSNorm}(h)),\qquad v=u+\operatorname{MLP}'_{\phi}(\operatorname{RMSNorm}(u)),\qquad h'=v+\operatorname{MLP}(\operatorname{RMSNorm}(v)). \]

    原有的 MLP 仍然是慢参数，为预训练得到的知识保留一个不会被测试时更新改写的位置；这一点和只更新最后四分之一的块，都沿用原论文的设计1。嵌入、归一化和注意力在测试时都不更新。

    2.3 内循环：先预测，后更新¶

    前段不依赖快权重，对整条序列只计算一次，得到特征 \(g_t=f^{\mathrm{pre}}_\theta(x_{1:t})\)。后段逐块计算。读完第 \(c\) 块后，这一块的平均损失是

    \[ \ell_c(\theta,\phi_{c-1})=\frac1C\sum_{t\in\mathcal T_c}-\log p\bigl(x_{t+1}\mid x_{1:t};\theta,\phi_{c-1}\bigr). \]

    注意预测第 \(c\) 块时用的是 \(\phi_{c-1}\)：它只见过前 \(c-1\) 块的目标。等第 \(c\) 块的目标全部成为已观测信息之后，才对快权重做一步梯度下降：

    \[ g_c=\nabla_{\phi}\,\ell_c(\theta,\phi)\Big|_{\phi=\phi_{c-1}},\qquad \hat g_c=\min\!\Bigl(1,\frac{\tau}{\lVert g_c\rVert_2}\Bigr)g_c,\qquad \phi_c=\phi_{c-1}-\eta\,\hat g_c . \]

    \(\eta\) 是内循环学习率，\(\tau\) 是对全部快权重合在一起计算的梯度范数上限。更新后的 \(\phi_c\) 只用于第 \(c+1\) 块及之后的预测，所以任何一个 token 的损失都不会用到见过它自己的权重，评测时不存在标签泄漏。序列末尾不足一块的部分只参与评分，不触发更新。

    后段的注意力带 KV 缓存：第 \(c\) 块可以看到窗口内前面各块的 key 和 value，它们是当时用旧的快权重算出来的，更新后不重算。

    2.4 外循环：学习怎样被更新¶

    训练目标是“按上述方式边读边更新之后”的平均损失：

    \[ \mathcal L(\theta)=\frac{1}{n_c}\sum_{c=1}^{n_c}\ell_c\bigl(\theta,\phi_{c-1}(\theta)\bigr),\qquad \phi_0\subset\theta . \]

    \(\phi_0\) 是慢参数的一部分，也就是说快权重的初值是学出来的。因为 \(\phi_{c-1}\) 是 \(\theta\) 的函数，\(\mathcal L\) 对 \(\theta\) 的梯度除了普通的反向传播，还要沿着更新链回传：

    \[ \frac{d\phi_c}{d\theta}=\frac{d\phi_{c-1}}{d\theta}-\eta\,\frac{d\hat g_c}{d\theta}, \]

    其中 \(d\hat g_c/d\theta\) 含有 \(\ell_c\) 对快权重的二阶导。实现上就是对整个带内循环的前向函数再求一次导（梯度的梯度）。慢参数因此学到两件事：怎样预测下一个 token，以及怎样让后段在被梯度更新之后预测得更好。

    消融实验里的一阶近似把 \(\hat g_c\) 当作常数，即令 \(d\hat g_c/d\theta=0\)。此时前向数值完全不变，训练更便宜，但外循环不再知道慢参数会怎样影响更新量。

    2.5 推理¶

    推理和训练时的内循环是同一个过程，只是不再有外循环。一个会话的状态由三部分组成：当前快权重 \(\phi\)（大小固定，与已读长度无关）、各层最近 \(w\) 个位置的 KV 缓存、以及尚未凑满一块的特征和目标。生成时每凑满 \(C\) 个 token 并观测到下一个 token，就执行一次更新。发布的慢参数不会被任何会话改动，不同会话之间也不共享快权重。

    2.6 实现要点¶

    实现基于 JAX，下面几点和结果的可信度直接相关。

    • 外循环梯度。 序列损失函数内部用 lax.scan 逐块前向并在每一步调用 jax.value_and_grad 得到 \(g_c\)，外层再对整个函数求导。块级扫描分成两层并加检查点，反传时只保存约 \(\sqrt{n_c}\) 份快权重快照，其余在反传时重算。
    • 滑窗注意力。 训练时前段对整条序列做滑窗注意力。我们把序列按 \(w\) 切块，每块只和自己以及前一块的 key 做稠密注意力，各块并行计算。在 float64 下它和逐位置掩码的参考实现最大相差 \(7\times10^{-7}\)（前向和对 query、key 的梯度都检查过），因此是同一个函数的另一种算法，不是近似。
    • 交叉熵。 词表投影和 log-softmax 按 token 分块计算；数值与一次性计算相同。
    • 精度。 参数为 float32；矩阵乘法用 bfloat16；归一化、softmax 和损失用 float32。
    • 正确性测试。 仓库的测试覆盖因果性（修改未来 token 不影响过去的输出）、外循环梯度与有限差分的一致性、流式推理与整段前向的一致性、检查点恢复，以及一阶近似“前向不变、梯度改变”这一性质；它们在 CPU 上全部通过。

    2.7 复杂度¶

    设每个 token 经过一个块的线性层成本为 \(c_{\mathrm{lin}}\)。全注意力每个 token 的注意力成本与已读长度成正比，KV 缓存也随长度线性增长。滑窗注意力和 TTT-E2E 的注意力成本都只与 \(w\) 有关。TTT-E2E 在此之上每个 token 多出两项：后段多一个 MLP′ 的前向，以及每块一次的后段反向传播（成本约为后段前向的两倍，再加输出层）。这两项都与已读长度无关，所以 TTT-E2E 的推理成本和状态大小对上下文长度是常数；代价是训练时要穿过内循环求二阶导。实测数字见第 4.10 节。

    3 实验设置¶

    3.1 四个模型¶

    主实验训练四个 12 层、宽度 768 的模型。它们使用同一个 tokenizer、同一份数据、完全相同的 batch 顺序、同样的优化器和同样的训练 token 数，只在“怎样使用上下文”上不同。

    模型 注意力 带 MLP′ 的块 测试时更新 总参数 非嵌入参数
    全注意力 可见全部 4,096 个位置 – – 123.57M 84.97M
    滑窗注意力 最近 \(w=512\) 个位置 – – 123.57M 84.97M
    无更新对照 最近 \(w=512\) 个位置 最后 3 块 不更新 137.73M 99.13M
    TTT-E2E 最近 \(w=512\) 个位置 最后 3 块 每 \(C=256\) 个 token 一步 137.73M 99.13M

    每个对照回答一个问题：

    • 全注意力是上下文内信息无损可见时的参照。它的成本随上下文线性增长，本报告把它看作质量上的目标，而不是成本上的对手。
    • 滑窗注意力是成本与 TTT-E2E 同量级的基线。它的每一层只能直接看到最近 512 个位置；更早的信息只能靠逐层接力间接传递（12 层在理论上最远可达约 6,100 个位置），模型没有专门的长程记忆。
    • 无更新对照与 TTT-E2E 结构相同、参数量相同（都比前两者多 14.16M 个 MLP′ 参数），训练和推理时都不做内循环。它用来区分“多出来的参数”和“测试时更新”各自的作用。
    • 评测时还会把训练好的 TTT-E2E 关闭更新再测一次，用来观察同一组慢参数在不更新时的表现。

    其余结构四者相同：\(d=768\)，12 个注意力头，\(d_{\mathrm{ff}}=2048\)，输入输出嵌入共享，RoPE 基数 \(5\times10^5\)，QK 归一化。

    3.4 评测协议¶

    Held-out 语言建模。 PG-19 test 的每本书从头切成互不重叠的 4,096 token 窗口（丢弃末尾不足一个窗口的部分），共 2,531 个窗口、10.37M 个预测位置。每个窗口从空状态开始：KV 缓存清空，快权重回到 \(\phi_0\)。于是窗口内第 \(t\) 个位置的损失，就是“恰好有 \(t\) 个 token 上下文时”的预测损失，按位置分桶即可得到损失随上下文长度变化的曲线。FineWeb-Edu held-out 的文档很短，按训练时的方式把文档首尾相接，取前 2,048 个窗口。我们报告每 token 的平均负对数似然（NLL，单位 nat）、困惑度和 bits/byte。

    统计。 四个模型评测的是同一批窗口，因此模型之间的差值按配对方式估计：PG-19 以书为单位、FineWeb-Edu 以窗口为单位做 2,000 次 bootstrap 重采样，给出 95% 置信区间。这个区间反映评测集的抽样误差，不包含重新训练带来的随机性；后者用第 4.9 节的多随机种子实验单独估计。

    超出训练长度。 把窗口加长到 32,768（训练长度的 8 倍），其余协议不变，不做任何微调。

    公开 benchmark。 所有任务都是零样本、按对数似然评分：多选题对每个候选项计算 \(\log p(\text{候选}\mid\text{题干})\) 并取最大者，提示模板、候选项拼接方式和长度归一化都与 lm-evaluation-harness23 的同名任务一致。为了确认这一点，我们用自己的评测脚本和 lm-evaluation-harness 分别评测 GPT-2，逐项对比（第 4.7 节）。不使用 few-shot 示例，不针对任何 benchmark 做训练、提示词搜索或检查点挑选；所有模型都只评测训练结束时的最后一个检查点。

    公开参考模型。 为了给出绝对水平的参照，用同一套脚本评测了一组规模相近的公开模型。它们的训练数据量比本报告的模型大一到三个数量级，这组数字用于定位，不是匹配预算的比较。

    4 结果¶

    4.1 训练过程¶

    四个模型最终都训练到 12,000 步、786,432,000 个 token，没有出现发散或 loss 尖峰。训练期间发生过用户级 NFS 磁盘配额导致的检查点写入中断；监督脚本从最近检查点自动恢复，并把事件写入 interruptions.jsonl。本次运行共记录 3 次自动恢复。梯度裁剪很少触发：预热之后，外循环梯度范数超过阈值 1.0 的记录步占 0.4%（滑窗注意力）和 0.6%（TTT-E2E）。

    训练损失不能直接横向比较。全注意力在训练时每个位置可以读到窗口内的全部历史，滑窗注意力只能读到最近 512 个位置，所以前者的训练损失天然更低；而 TTT-E2E 的训练损失是“已经按测试时的方式更新过快权重”之后的损失，和另外两者的含义也不同。图 2 左只用于确认四个运行都稳定收敛。可比的是中、右两栏：同一个评测协议、同一批 held-out 窗口。

    从验证曲线可以看出一个和最终数字同样重要的现象：TTT-E2E 从训练早期就领先于滑窗注意力，而且差距在整个训练过程中没有缩小（图 7 右）。这说明收益不是“训练不足时的暂时优势”。 TTT-E2E 的内循环在训练过程中始终处于活跃状态。快权重范数从初值 75.3 增长到 132.5，每次内循环更新的范数稳定在 0.98 附近，内循环梯度范数在 1.22 左右——它略大于裁剪阈值 \(\tau=1\)，也就是说多数更新步都被裁剪到了固定步长。换句话说，外循环学到的是“在固定步长下，朝哪个方向更新最有用”，而不是“更新多大”。这一点在第 4.8 节的内循环学习率消融中可以看到对应的现象。

    4.4 收益来自哪里¶

    TTT-E2E 与滑窗注意力的差别有三个来源：后段多了一个 MLP′（额外参数）、推理时执行梯度更新（测试时计算）、以及训练时就在模拟这种更新（元学习）。四个模型加上两项专门的评测，可以把三者分开。

    额外参数本身。 无更新对照与 TTT-E2E 结构相同、参数量相同，训练和推理都不做内循环。它比滑窗注意力低 0.023 nat（[−0.024, −0.022]）——多出来的 14.2M 个参数确实有用，但只解释了总差距 0.072 nat 中的一小部分。

    测试时更新本身。 TTT-E2E 比无更新对照低 0.049 nat（[−0.052, −0.046]）。两者参数量和结构完全相同，差别只有"推理时是否按内循环更新快权重"以及"训练时是否模拟了这一过程"。这是三项里最大的一项。 没有元学习的测试时更新够不够？ 这是关键的一问：如果对任意一个普通模型直接做测试时梯度下降（动态评估）就能得到同样的收益，那么训练阶段的二阶导就是不必要的开销。我们对无更新对照直接执行同一套内循环，并扫描测试时学习率。结果是几乎没有改善：最好的一档是 3.0456，而不更新时是 3.0552。同一组超参数作用在经过元训练的 TTT-E2E 上，则从 3.0793 降到 3.0078。

    换句话说，有用的不是梯度更新这个动作，而是模型事先被训练成"可被这样更新"。这正是端到端训练二阶导的代价所换来的东西。 还有一个方向相反的观察值得记录：把训练好的 TTT-E2E 关闭更新后评测，它比无更新对照差 0.029 nat（[+0.026, +0.032]）。用更新训练出来的慢参数会依赖这些更新：它们把一部分建模工作交给了内循环，拿掉内循环就留下缺口。这意味着 TTT-E2E 不是一个"可以随时关掉以省算力"的功能，而是一个必须成套使用的设计。

    逐字回忆。 把窗口内一段 64 个 token 的原文原样复制到更靠后的位置，看模型在重复段上的损失比未改动文本降低多少。注意力可以直接回看原文，所以全注意力在距离 320 处降低 1.83 nat，并随距离缓慢衰减到 0.52 nat。

    滑窗注意力的表现是一道断崖：距离 320（仍在 512 窗口内）时降低 1.51 nat，一旦超出窗口就归零甚至变为负值（距离 640 时 −0.11）。窗口之外，它对自己读过的原文没有任何记忆。

    TTT-E2E 填上了这道断崖，但填的方式与注意力不同：距离 640 处降低 0.61 nat，而且此后几乎不随距离衰减（3,712 处仍有 0.58 nat）。这正是"压进权重"应有的特征——信息不是按距离远近排列的，而是被累积进一组权重里。代价同样明显：它的绝对量只有全注意力的一半左右，压缩确实有损。 单针检索。 按 RULER 的 niah 任务构造：在干草堆文本里藏一句"某个键对应的特殊数字是 ⟨7 位数⟩"，然后提问。这些模型都是 1.3 亿参数的基座模型，没有指令微调，直接按精确匹配评分全部为零——这样的全零结果说明不了任何问题。因此我们改为度量"针在场 vs 针被换成无关键值对"时答案对数似然的差：它衡量模型是否真的用到了那根针，即使它说不出完整答案。

    在 32K 上下文下，TTT-E2E 的这一指标是 1.32 nat/token，滑窗注意力是 0.37，无更新对照是 0.41。滑窗和无更新对照的数值随上下文变长而持续下滑（针被推到窗口之外），TTT-E2E 则从 4K 到 32K 基本持平。 两个探针指向同一个结论：TTT-E2E 保留的是随上下文长度稳定、但精度受限的记忆，而注意力保留的是精确、但受窗口或成本限制的记忆。它们不是同一种东西，这也是原论文在针尖检索类任务上落后于全注意力的原因。

    但三个点不足以拟合任何趋势，而且它们都在同一个很小的规模区间内、用同一个数据量。原论文在 1.25 亿到 30 亿参数上报告收益随规模变化的情况，本报告无法验证也无法反驳那一结论。

    这项检查有两个已知的盲区。第一，它只能发现逐字重合，发现不了改写、翻译或只重合答案的情况。第二，题干规范化后不足 50 个字符的题目没有参与检查（表中“检查的题目数”小于题目总数的原因），PIQA 和 OpenBookQA 因此只覆盖了一部分题目。

    训练集与 held-out 集之间的重复。 PG-19 使用官方划分。按规范化全文的摘要比对，validation 和 test 的 150 本书没有一本与训练集的 28,602 本书全文相同；按 PG-19 元数据里的“书名 + 作者”比对，也没有与训练集同名的书。FineWeb-Edu 的 held-out 取自训练没有用到的分片，但网页语料里存在跨分片的重复：最初取出的 20,000 篇里有 365 篇（1.8%）与训练分片中的某篇文档全文相同。这些文档已经从 held-out 集中剔除，本报告的所有 FineWeb-Edu 数字都在剔除之后的集合上计算。近似重复（例如只差页眉页脚的网页）没有检查。

    训练时实际读到了什么。 采样器按训练种子重放的结果见第 3.2 节：两个来源的实际比例与 50/50 的目标相差不到 0.2 个百分点；整个训练只覆盖了 FineWeb-Edu 训练分片的 19.7% 和 PG-19 训练集的 14.8%，被读到的文本里约九成只读到一次。训练因此接近单遍训练，模型几乎没有机会靠重复来记住训练文本。

    6 讨论与局限¶

    本报告测到了什么。 在固定 token 预算、严格匹配数据和超参数的条件下，TTT-E2E 在两个 held-out 集上都优于全注意力和滑窗注意力，优势在三个随机种子和三种模型规模下重复出现。把收益拆开后，最大的一项来自测试时更新本身，其次是额外参数；而对未经元训练的模型直接做同样的梯度更新几乎没有效果，说明有价值的是"被训练成可更新"，而不是更新这个动作。两个探针显示它保留的是随距离稳定、但精度低于注意力的记忆。

    本报告没有测到什么。 规模。四个主模型都是 1.3 亿参数、7.86 亿 token——约为原论文最小档配方的 31%，比它最大的实验小两个数量级。第 4.9 节的三个规模点都落在很窄的区间内，不足以说明趋势。上下文同样：训练长度 4,096，评测最远到 32,768，而原论文的主张是在 128K 上。本报告既不能确认也不能否定那个规模下的结论。

    最重要的保留意见。 第 4.8 节的等训练时间对照是这份报告里最不利于 TTT-E2E 的结果：同样的墙上时间，滑窗基线多读 3.7 倍数据，损失明显更低。这不是实现效率的问题——穿过内循环求二阶导有固有成本，而且原论文自己也把训练延迟列为主要限制。因此本报告的结论应当这样陈述：在数据受限（token 预算固定）时，TTT-E2E 用额外计算换来了更好的模型；在计算受限时，同样的计算用于多读数据更划算。 这两种情形在实践中都存在，哪一种适用取决于具体约束，而不是方法本身的优劣。

    一条有实用价值的负面结果。 一阶近似（不对内循环梯度求导）在这个规模上与完整二阶导相当甚至略好，而训练更便宜。如果这一点在更大规模上成立，它会显著改变上一段的成本权衡；本报告的规模不足以验证。

    一个需要注意的性质。 用更新训练出来的慢参数会依赖这些更新：关闭更新后，模型比从未使用过更新的同构对照更差。TTT-E2E 因此不是一个可以在推理时按需关闭以节省算力的开关，而是一套必须整体采用的设计。这对部署有直接影响。

    与原论文的关系。 方向一致的有：TTT-E2E 在匹配预算下优于基线，推理成本与上下文长度无关，长上下文下优势扩大，以及针尖检索类任务弱于全注意力。本报告在小得多的规模上独立复现了这些定性结论，并补上了原论文未报告的几项分解（无更新对照、动态评估基线、等时间对照、一阶近似）。原论文关于 128K 上下文和 30 亿参数的定量主张，本报告既未验证也未反驳。

    7 适用范围与发布说明¶

    • 模型性质。 四个主实验模型都是只做过预训练的小型英文基座语言模型，没有经过指令微调、对话微调或任何安全对齐训练。它们适合研究序列建模方法，不适合直接面向用户，也不应把它们的输出当作事实来源。
    • 数据许可。 训练只使用两种公开语料：FineWeb-Edu（ODC-By 1.0）和 PG-19（公有领域书籍文本，数据集卡片为 Apache-2.0）。仓库不再分发语料本身，只提供下载脚本、固定的 revision 和文件摘要。评测集按各自的许可只下载评测划分，不进入训练。
    • 内容风险。 FineWeb-Edu 来自网页，PG-19 是 1919 年之前出版的书籍，其中有与当代规范不符的表述，模型会复现训练语料中的偏见和过时内容。本报告没有做毒性、偏见或越狱评测，这些是面向用户发布之前必须补上的工作，而不是这一版声称已经完成的事。
    • 测试时更新特有的风险。 快权重只存在于单个会话里，会话结束即丢弃，发布的慢参数不会被用户输入改写；实现上不同会话的快权重和缓存相互隔离。但在会话内部，模型的行为会随读到的内容漂移，这既是方法的目的，也意味着长会话里的行为比固定权重的模型更难事先界定。第 4.5 节给出了快权重在 32K token 内的漂移幅度。
    • 本报告不声称的事。 不声称达到同规模模型的最好水平（第 4.7 节的公开模型在多数任务上更强，它们的训练量大得多）；不声称结论在更大的模型、更长的训练或更长的窗口下必然成立；不声称与任何闭源模型可比。
